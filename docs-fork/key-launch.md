# 配置菜单

入口：**管理后台 → 设置 → 自定义菜单**。每个菜单项底部的**「高级选项」**是 fork 专属配置。

## 两个通用开关

| 字段 | 默认 | 说明 |
|---|---|---|
| 打开方式 | 内嵌 | `新窗口打开` 适合外部站点（对方禁止 iframe 时必须选它） |
| 附带用户参数 | 开 | 会往目标链接追加 `user_id`、`token` 等。**指向第三方站点时关掉**，否则等于把用户登录凭证交出去 |

## 场景一：普通菜单改新窗口打开

1. 找到菜单项，展开「高级选项」
2. 打开方式选`新窗口打开`
3. 目标是外部站点就取消勾选「附带用户参数」
4. 保存

URL 不用改。

## 场景二：配置 `plus:key_launch`

想让用户点一下菜单，就带着可用的 API 密钥跳到外部站点。

**先准备好**

- 一个**分组**（管理后台 → 分组），并确认用户对该分组有权限
- 可选：一个**充值菜单项**，用作余额不足时的落点

**步骤**

1. 自定义菜单 → 添加菜单项
2. **名称**：用户看到的文字
3. **URL**：填 `plus:key_launch`
4. **可见性**：用户 / 管理员
5. 展开**「高级选项」**，填：

   | 字段 | 填什么 |
   |---|---|
   | 打开方式 | 外部站点选`新窗口打开` |
   | 附带用户参数 | 外部站点**取消勾选** |
   | 分组 | 密钥放在哪个分组 |
   | 「去充值」按钮指向 | 留空 = 默认充值页；或选一个已有菜单 |
   | 链接模板 | 目标地址，用 `{key}` 表示密钥位置 |

6. 保存。缺必填项时卡片会红字提示，后端也会拒绝保存

**链接模板写法**

```
https://console.example.com/#/?apiKey={key}
```

三条规则：

- 必须含 `{key}`，否则保存不了
- 替换后必须是完整的 `http(s)://` 地址
- **`{key}` 不能放在域名里**（如 `https://{key}.example.com/`），这种保存能过但点击时报错

## 用户点击后

后端按顺序检查，任何一步不过就在页面上显示原因和按钮：

| 检查 | 不过时的提示 | 按钮 |
|---|---|---|
| 分组可用 | 该分组当前不可用 | — |
| 用户有权限 | 您暂无该分组的访问权限 | 去开通 |
| 余额 / 订阅足够 | 余额不足，请先充值后再使用 | 去充值 |
| 专属密钥可用 | 额度已用完 / 已过期 | 去管理 |

都通过就自动建好密钥、填进模板、打开链接。

密钥名固定是 `自动创建（请勿改名）`。**改了名会被当成不存在**，下次点击新建一把，用户就会看到两把——别改名。

## 调整与删除

- **换分组**：改下拉即可。已建的密钥不迁移，下次点击在新分组另建一把
- **改模板**：立即生效
- **删菜单**：密钥不跟着删，用户仍能在 API 密钥页看到并继续用。要收走权限得去停用那把密钥

## 用户说打不开

看页面上那句原因，对照上表。另外两个常见情况：

- **内嵌白屏** → 对方站点禁止 iframe，改成`新窗口打开`
- **对方收不到用户信息** → 「附带用户参数」被关了

后端直接返回的错误：

| 状态码 | 含意 |
|---|---|
| 401 | 没登录 |
| 404 | 菜单不存在，或该菜单仅管理员可见而调用者不是管理员 |
| 400 | 该菜单 URL 不是 `plus:key_launch` 开头（多半是模块名打错） |
| 500 | 配置损坏，检查菜单配置是否完整 |
